## 1. 项目简介

- **语言标准**：C++17
- **构建系统**：CMake（最低 3.20）
- **目标平台**：Windows (MSVC)、Linux x86_64 (GCC / Clang)、Android ARM64 (Termux)
- **构建目标**：`Program`（Windows 下为 `Program.exe`）
- **依赖策略**：所有第三方依赖随仓库提供并从源码编译，构建过程**无需外部包管理器、无需联网下载**

---

## 2. 环境要求

| 平台 | 要求 |
|------|------|
| **Windows** | Visual Studio 2022（含 MSVC x64 工具链）、CMake 3.20+ |
| **Linux x86_64** | clang / gcc、CMake 3.20+、perl、make、pkg-config |
| **Android ARM64** | Termux（原生编译）：`pkg install clang cmake make perl pkg-config` |

> 交叉编译 Windows → Linux 时还需：clang、lld，以及目标 `x86_64-linux-gnu` 的 sysroot。

## 3. 获取源码

```bash
git clone https://github.com/LKIQBoost/OPEN_NTVECTOR.git
cd OPEN_NTVECTOR
```

仓库包含全部第三方依赖源码（OpenSSL、Python 2.7、jsoncpp、libdatachannel、libwebsockets、SLikeNet、zlib），无需单独下载。

---

## 4. Windows 构建

在**开发者命令提示符**（Developer Command Prompt）中执行：

```bash
cmake -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release
```

- 生成器：`Visual Studio 17 2022`
- 架构：`x64`
- 产物：`build/Release/Program.exe`

也可以在 Visual Studio 中直接打开仓库根目录，使用 CMake 列表（Configure → Build）。

---

## 5. Linux 构建

### 原生编译

```bash
cmake -B build -DCMAKE_C_COMPILER=clang -DCMAKE_CXX_COMPILER=clang++
cmake --build build -j$(nproc)
```

- 首次构建会把 OpenSSL 与 Python 2.7 从源码编译，耗时约 5-10 分钟
- 产物：`build/Program`
- 后续构建复用缓存，明显加快

### 依赖项

Debian / Ubuntu 系安装依赖：

```bash
sudo apt install cmake clang perl make pkg-config
```

## 6. Android / Termux 构建

Termux 中**原生编译**（不需要交叉编译工具链）：

```bash
pkg install clang cmake make perl pkg-config
cmake -B build
cmake --build build -j$(nproc)
```

平台检测由 `cmake/Platform.cmake` 自动完成（检测到 Bionic libc 即进入 `PLATFORM_ANDROID` 分支）。也可手动指定：

```bash
cmake -B build -DPLATFORM_ANDROID=ON
```

---

## 7. 交叉编译（Windows → Linux）

从 Windows 交叉编译 Linux x86_64 二进制，使用仓库自带的工具链文件（clang + lld）：

```bash
cmake -B build-linux-x64 \
  -DCMAKE_TOOLCHAIN_FILE=cmake/toolchains/linux-clang-x86_64.cmake \
  -DCMAKE_SYSROOT=/path/to/x86_64-linux-gnu-sysroot
cmake --build build-linux-x64
```

> `CMAKE_SYSROOT` 指向目标平台的 sysroot（其中需包含 GNU 工具链的头文件与库）。工具链默认 `-target x86_64-linux-gnu`、链接器使用 `lld`。

## 8. 构建产物与运行

### 产物位置

| 平台 | 路径 |
|------|------|
| Windows | `build/Release/Program.exe` |
| Linux / Android | `build/Program` |

### 运行目录

程序运行于部署目录，需要以下文件（请勿删改 `source/`，那是运行环境）：

```
部署目录/
├── Program.exe          # 主程序
├── mc.cfg               # 启动配置（JSON，可选，也可用命令行参数）
├── client_cfg.json      # 客户端配置（JSON：no_launch_mcp 等）
├── skin_data.json       # 皮肤数据
├── source/              # Python 运行环境（vanilla.mcp / lib/）
└── scripts/             # 插件目录
```

### 常用启动参数

```bash
Program.exe --config mc.cfg --logger
Program.exe --start_nethernet --UserID xxx --DisplayName xxx --MD5Token xxx
```

> 完整参数表见仓库 README「命令行参数」一节；插件开发见《插件开发文档》。

## 9. 依赖说明

所有依赖均从源码编译，构建过程无需联网。

| 库 | 版本 | 构建方式 |
|----|------|----------|
| OpenSSL | 3.5.0 | cmake 配置期自动构建（`cmake/BuildOpenSSL.cmake`），缓存于 `build/_deps/`；Windows 失败时回退到项目自带 `.lib` |
| Python 2.7 | 2.7.18（定制） | Linux / Android 从源码构建（`cmake/BuildPython27.cmake`）；Windows 使用预编译 `.lib` |
| jsoncpp | 1.9.6 | `add_subdirectory` |
| libdatachannel | 最新 | `add_subdirectory`（含 libjuice、libsrtp、usrsctp） |
| libwebsockets | 4.5 | `add_subdirectory` |
| SLikeNet | 定制（RakNet 魔改） | `add_subdirectory` |
| zlib | 1.3.1 | `add_subdirectory` |

### Python 2.7 构建细节（排障用）

- **强制内置扩展模块**：通过生成的 `Modules/Setup.local` 将 `datetime`、`math`、`zlib`、`_socket` 等静态编入 `libpython2.7.a`，避免嵌入式运行时找不到 `.so`
- **GCC 15+ 兼容**：`CFLAGS=-std=gnu11`（C23 下 `bool`/`true`/`false` 成为关键字，与 Python 2.7 冲突）
- **Android Bionic 限制**：`config.site` 禁用 `getloadavg`、`setpwent`、`forkpty` 等缺失函数
- **安装步骤**：`make altbininstall inclinstall libainstall`，失败时回退为手动复制 `.a` + `Include/`

## 10. 常见问题

### Q: 首次构建很慢？

A: 正常。OpenSSL 与 Python 2.7 需要从源码编译，约 5-10 分钟。产物缓存在 `build/_deps/`，下次构建跳过。

### Q: 推送代码到 GitHub 时报 `RPC failed; curl 65 ... Connection was reset`？

A: 仓库历史较大（含 57MB 的 `libcrypto_static.lib`），需要增大 HTTP 缓冲区：

```bash
git config http.postBuffer 524288000
```

### Q: 提示 `libcrypto_static.lib` 超过 50MB 推荐上限？

A: 仅警告，不影响。GitHub 单文件上限 100MB。如需精简仓库，可改用 Git LFS 或重写历史。

### Q: Linux / Android 上 `Python.h` 找不到？

A: 删除 `build/_deps/` 后重新 configure（Python 构建产物损坏时也会出现）。若仍失败，检查 `perl`、`make`、`pkg-config` 是否已安装。

### Q: 可以只构建客户端、不构建 Python 吗？

A: 不能。Python 2.7 是运行时的脚本引擎（见《插件开发文档》），是链接依赖，不是可选项。

## 1. 项目简介

- **语言标准**：C++17
- **构建系统**：CMake（最低 3.20，兼容 CMake 4.x）
- **目标平台**：**Windows (MSVC) 为主**；Linux x86_64 / Android ARM64 (Termux) 为历史支持（见第 6 节）
- **构建目标**：`Program`（Windows 下为 `Program.exe`）
- **内嵌运行时**：Python **3.12.2**，从 `third_party/Python-3.12.2` 编出**静态**核心库链进 exe，运行时不需要 `python312.dll`
- **依赖策略**：第三方 C/C++ 依赖随仓库提供并从源码编译，构建过程**无需外部包管理器、无需联网下载**（Python 3.12 除外，见第 7 节）

## 2. 环境要求

| 平台 | 要求 |
|------|------|
| **Windows** | Visual Studio 2026（MSVC，x64，需 `v145` 工具集）、CMake 4.x（最低 3.20）、**宿主 Python ≥ 3.10** |
| **Linux x86_64** | 历史支持（clang / gcc）；Py3 迁移后构建脚本待更新 |
| **Android ARM64** | 历史支持（Termux 原生编译）；同上待更新 |

**Python 运行时不再依赖本机安装**：解释器核心由 `cmake/BuildPython312.cmake` 在
configure 期从仓库内的 `third_party/Python-3.12.2` 编成静态库并链进 `Program.exe`，
运行时不需要 `python312.dll`。

> 但 configure 期需要**一个 ≥ 3.10 的宿主 Python**，仅用于跑
> `Tools/build/deepfreeze.py` 生成冻结模块（不参与链接，版本不必与 3.12.2 一致）。
> 未指定时自动探测（PATH → `%LOCALAPPDATA%\Programs\Python\Python312` → `py -3`）；
> 也可显式指定：`-DNTVECTOR_PY_HOST=C:/path/to/python.exe`。
>
> 相关 CMake 选项：
>
> | 变量 | 默认 | 说明 |
> |------|------|------|
> | `NTVECTOR_PY_HOST` | 自动探测 | 宿主 Python（≥ 3.10） |
> | `NTVECTOR_PY_TOOLSET` | `${CMAKE_VS_PLATFORM_TOOLSET}`，否则 `v145` | **必须显式**：CPython 的 `python.props` 对未知 VS 版本会静默回落到本机没装的 `v140` |
> | `NTVECTOR_PY_WINSDK` | `${CMAKE_VS_WINDOWS_TARGET_PLATFORM_VERSION}`，否则 `10.0.26100.0` | Windows SDK 版本 |
> | `NTVECTOR_PY_REBUILD` | `OFF` | 置 `ON` 强制重建静态核心 |

## 3. 获取源码

```bash
git clone https://github.com/LKIQBoost/OPEN_NTVECTOR.git
cd OPEN_NTVECTOR
```

仓库包含全部第三方 C/C++ 依赖源码（OpenSSL、jsoncpp、libdatachannel、libwebsockets、SLikeNet、zlib），无需单独下载。

## 4. Windows 构建

在项目根目录执行：

```bash
cmake -B build -G "Visual Studio 18 2026" -A x64
cmake --build build --config Release
```

- 生成器：`Visual Studio 18 2026`
- 架构：`x64`
- 产物：`build/application/Release/Program.exe`

> **首次 configure 会多花几分钟**：要从 `third_party/Python-3.12.2` 编静态 CPython 核心
> （先编 `_freeze_module` 生成冻结模块，再编 ~198 个核心源文件）。产物和指纹缓存在
> `build/_deps/python-static/`，之后 configure 直接命中缓存。
> 生成的文件包括 `third_party/Python-3.12.2/Python/frozen_modules/*.h` 与
> `Python/deepfreeze/deepfreeze.c`（已 gitignore），以及
> `build/generated/ntvector_python_builtin_inittab.inc`。

> **构建坑（必读）**：
> 1. 改 header（如 `engine_wrapper.h`）后 MSBuild 增量编译**不会**重编依赖它的 .cpp，需 `touch` 该 .cpp 强制重编，否则部署的是旧代码。
> 2. 构建行为异常时优先 `rm -rf build` 重新 configure——**不要复用损坏的旧 CMake 构建目录**。
> 3. 含中文注释的新增源码要存成 **UTF-8 带 BOM**，否则 MSVC 在 GBK 代码页下注释尾字节吞换行（`C4819`/`C2039`）。

也可以在 Visual Studio 中直接打开仓库根目录，使用 CMake 列表（Configure → Build）。

## 5. 构建产物与部署

### 产物位置

| 平台 | 路径 |
|------|------|
| Windows | `build/application/Release/Program.exe` |
| Linux / Android | `build/Program`（历史） |

### 运行位置

实际运行位置为 **`D:/Game/Minecraft/Vector/`**：

```
D:/Game/Minecraft/Vector/
├── Program.exe          ← CPython 3.12 核心静态链在里面，不需要 python312.dll
├── source/              ← 运行环境
│   ├── Lib/             ← 标准库（原 python312/Lib 移到这里）
│   │   └── site-packages/ ← 第三方库装这里；含 umsgpack.py、RC4.py、chacha/、raknet/、*.pyi
│   ├── init.py          ← 框架：加载插件 / 处理 RPC 反作弊校验
│   ├── proton.py        ← 解析数据包
│   └── redirect.py      ← 遗留
├── scripts/             ← 插件（每个插件一个目录）
└── mc.cfg / client_cfg.json / skin_data.json / skins/ / songs/
```

> **去掉的**：`python312.dll`、`python3.dll`、整个 `python312/` 目录（含 `DLLs/*.pyd`）。
> 解释器核心静态链在 `Program.exe` 里，与 Python 2.7 时代的形态一致。
> 标准库从 `python312/Lib` 移到 `source/Lib` —— `Program.exe` 用 `PYTHONHOME=<exe>\source`
> 定位它（Windows 上 `getpath` 找的是 `Lib\os.py` 这个 landmark）。

> 请勿删改 `source/`，那是运行环境（框架脚本 + 标准库）；插件放 `scripts/`。

#### 从旧布局迁移（含回滚）

先关掉正在运行的客户端，然后：

```bat
cd /d D:\Game\Minecraft\Vector
mkdir backup_py312
move python312       backup_py312\
move python312.dll   backup_py312\
move python3.dll     backup_py312\
mkdir source\Lib
xcopy /E /I /Y python312\Lib\* source\Lib\
move Program.exe backup_py312\Program_old.exe
copy <新构建>\Program.exe .
```

迁移完 `source/Lib` 应直接含 `os.py`、`importlib\`、`site-packages\` 等（即原来
`python312/Lib` 的内容）。`backup_py312` 里那份 `Lib` 确认新 exe 跑通后即可删除。

回滚：把 `backup_py312` 里的 `Program_old.exe` 改名回 `Program.exe`，把
`python312` / `python312.dll` / `python3.dll` 移回原位，删掉 `source\Lib`。

#### 上线前的硬门槛

必须实测一次真实连服：`PlayStatus value: 3`（PlayerSpawn，正常进服）**且没有被
"因违规游戏行为"踢出**。静态化改动了初始化路径，MCP 反作弊校验链
（rotor + umsgpack + RC4）必须实测确认，`log.txt` / `dis.log` 里不应出现相关封禁。

### 常用启动参数

```bash
Program.exe --config mc.cfg --logger
Program.exe --start_nethernet --UserID xxx --DisplayName xxx --MD5Token xxx
```

> 完整参数表见仓库 README「命令行参数」一节；插件开发见《插件开发文档》。

### 运行检查

- 日志：`log.txt`（完整）、`dis.log`（断开 / 封禁）
- `PlayStatus value: 3` = **PlayerSpawn（正常进服）**，不是错误；`0` = 登录成功；`1/2/4/5/6` 才是失败
- 反作弊封禁"因违规游戏行为，您的账号被禁止进入游戏" = RPC/MCP 校验链有问题（详见《项目架构与 Py3 迁移》）

## 6. Linux / Android（历史支持）

> ⚠️ 以下内容为**历史构建方式，目前未回归验证**。
> 现状：`cmake/BuildPython312.cmake` 只对 `WIN32 AND MSVC` 生效（非该平台直接 `return()`），
> 其他平台会回落到 `application/CMakeLists.txt` 里的
> `find_package(Python3 3.12 COMPONENTS Development REQUIRED)` + `Py_ENABLE_SHARED`
> 动态链接分支。如需恢复 Linux / Android 的**静态**支持，需先：
> 1. 让 `BuildPython312.cmake` 支持非 Windows：Linux 用 CPython 的 `./configure --disable-shared`
>    产出 `libpython3.12.a`（Python 2.7 时代的 `BuildPython27.cmake` 就是这条路，可以参考）；
> 2. 同步 `cmake/PythonBuiltinModules.cmake` 的白名单（部分模块是 Windows 专属，
>    如 `winsound` / `_overlapped` / `_multiprocessing` 的源文件）；
> 3. 重新验证 OpenSSL / libdatachannel 等依赖在目标平台的构建。

### Linux x86_64 原生编译（历史命令）

```bash
cmake -B build -DCMAKE_C_COMPILER=clang -DCMAKE_CXX_COMPILER=clang++
cmake --build build -j$(nproc)
```

### Android / Termux 原生编译（历史命令）

```bash
pkg install clang cmake make perl pkg-config
cmake -B build
cmake --build build -j$(nproc)
```

平台检测由 `cmake/Platform.cmake` 自动完成（检测到 Bionic libc 即进入 `PLATFORM_ANDROID` 分支）。也可手动指定 `-DPLATFORM_ANDROID=ON`。

### 交叉编译（Windows → Linux，历史）

```bash
cmake -B build-linux-x64 \
  -DCMAKE_TOOLCHAIN_FILE=cmake/toolchains/linux-clang-x86_64.cmake \
  -DCMAKE_SYSROOT=/path/to/x86_64-linux-gnu-sysroot
cmake --build build-linux-x64
```

> 工具链文件默认 `-target x86_64-linux-gnu`、链接器用 `lld`；`CMAKE_SYSROOT` 需包含目标平台的 GNU 工具链头文件与库。

## 7. 依赖说明

| 库 | 版本 | 构建方式 |
|----|------|----------|
| Python | 3.12.2 | 源码在 `third_party/Python-3.12.2`，configure 期编出静态核心库（`cmake/BuildPython312.cmake`）链进 `Program.exe`；运行时不需要 `python312.dll` |
| OpenSSL | 3.5.0 | cmake 配置期自动构建（`cmake/BuildOpenSSL.cmake`），缓存于 `build/_deps/`；Windows 失败时回退到项目自带 `.lib` |
| jsoncpp | 1.9.6 | `add_subdirectory` |
| libdatachannel | 最新 | `add_subdirectory`（含 libjuice、libsrtp、usrsctp） |
| libwebsockets | 4.5 | `add_subdirectory` |
| SLikeNet | 定制（RakNet 魔改） | `add_subdirectory` |
| zlib | 1.3.1 | `add_subdirectory` |

### 静态 CPython 核心（排障用）

- **链接**：`python312core.lib`，由 `cmake/BuildPython312.cmake` 在 configure 期生成，
  缓存在 `build/_deps/python-static/out/amd64/`。工程补丁副本在
  `build/_deps/python-static/proj/pythoncore_static.vcxproj`，构建日志
  `build/_deps/python-static/{freeze,core}.log`。
- **链接宏**：核心保留 `Py_ENABLE_SHARED` + `Py_BUILD_CORE`（否则 `Py_EXPORTED_SYMBOL`
  为空、API 不导出）；应用侧用 `Py_NO_ENABLE_SHARED`，由 `python312core` 的 INTERFACE
  定义自动下发；`PYBIND11_EXPORT` 置空以避开 `C2375`。
- **部署**：`source/Lib` 取自本机 Python 3.12.2 的 `Lib/`（裁剪到约 27MB，去掉
  `__pycache__`/`test`/`tkinter`）；`umsgpack.py`/`RC4.py`/`chacha/`/`raknet/` 在
  `Lib/site-packages/`。**不再需要** `DLLs/`、`python312.dll`、`python3.dll`。
- **旧 Py2 形态**：当年是静态 `python27.lib`（32 MB，由 `Python-2.7.18/PCbuild` 的
  `pythoncore` 工程产出）+ `source/lib` 标准库，`Program_py27.exe` 仅作备份。
- **`third_party/Python-3.12.2` 是剪裁过的**：为控制仓库体积，已从 python.org 源码
  tarball 中删去 `Doc/`、`Misc/`、`Mac/`、`Lib/test/`、`PCbuild/obj/`（112 MB → 59 MB）。
  构建需要的东西都在，详见 `cmake/BuildPython312.cmake` 顶部的"必须保留"清单。

## 8. 常见问题

### Q: 首次构建很慢？

A: 正常。OpenSSL 需要从源码编译（约 5-10 分钟），另外**首次 configure 还要编一遍
静态 CPython 核心**（先 `_freeze_module` 再 ~198 个核心源文件，约几分钟）。两者产物都
缓存在 `build/_deps/`，之后 configure 跳过。

### Q: configure 报 "Host Python not found" / "MSBuild.exe not found"？

A: 静态核心的构建需要两样东西：

1. **一个 ≥ 3.10 的宿主 Python**（只用来跑 `Tools/build/deepfreeze.py`，不参与链接）——
   自动探测走 PATH → `%LOCALAPPDATA%\Programs\Python\Python312` → `py -3`；
   探测不到就用 `-DNTVECTOR_PY_HOST=C:/path/to/python.exe` 指定。
2. **MSBuild.exe** —— 走 `CMAKE_VS_MSBUILD_COMMAND` → `vswhere.exe` → PATH。

### Q: 静态核心构建失败，或者换机器/换工具集后行为不对？

A: 看 `build/_deps/python-static/{freeze,core}.log`（脚本报错时会把路径打出来）。
构建缓存带指纹（`pythoncore.vcxproj`/`_freeze_module.vcxproj`/`pyconfig.h`/工具集/SDK
的 SHA1），任一变化会自动重编。要强制重建：`cmake -B build -DNTVECTOR_PY_REBUILD=ON`。

### Q: 改 `third_party/Python-3.12.2` 里的东西后 configure 报 patch anchor not found？

A: `cmake/BuildPython312.cmake` 会对 `PCbuild/pythoncore.vcxproj` 打 7 处补丁，
锚点按 3.12.2 原文写死。升级 CPython 版本要同步核对那几处锚点，不要直接手改源码树
（脚本生成补丁副本到 build 目录，就是为了不污染 `third_party/`）。

### Q: 改完 header 重新构建，但运行还是旧行为？

A: MSBuild 增量编译不重编依赖该 header 的 .cpp。用 `touch <依赖的.cpp>`（如 `CallbackManger.cpp`）强制重编，或直接 `rm -rf build` 全量重建。

### Q: 推送代码到 GitHub 时报 `RPC failed; curl 65 ... Connection was reset`？

A: 仓库历史较大（含 57MB 的 `libcrypto_static.lib`），需要增大 HTTP 缓冲区：

```bash
git config http.postBuffer 524288000
```

### Q: 提示 `libcrypto_static.lib` 超过 50MB 推荐上限？

A: 仅警告，不影响。GitHub 单文件上限 100MB。如需精简仓库，可改用 Git LFS 或重写历史。

### Q: Linux / Android 上 `Python.h` 找不到？

A: Py3 迁移后非 Windows 构建尚未支持（见第 6 节）。历史 Py2 构建时该问题由损坏的 `build/_deps/` 导致，删除后重新 configure 即可。

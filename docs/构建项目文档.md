## 1. 项目简介

- **语言标准**：C++17
- **构建系统**：CMake（最低 3.20，兼容 CMake 4.x）
- **目标平台**：**Windows (MSVC) 为主**；Linux x86_64 / Android ARM64 (Termux) 为历史支持（见第 6 节）
- **构建目标**：`Program`（Windows 下为 `Program.exe`）
- **内嵌运行时**：Python **3.12.2**，链接本机开发安装的 `python312.lib`，运行时部署 exe 旁 `python312/`
- **依赖策略**：第三方 C/C++ 依赖随仓库提供并从源码编译，构建过程**无需外部包管理器、无需联网下载**（Python 3.12 除外，见第 7 节）

## 4. Windows 构建

在项目根目录执行：

```bash
cmake -B build -G "Visual Studio 18 2026" -A x64
cmake --build build --config Release
```

- 生成器：`Visual Studio 18 2026`
- 架构：`x64`
- 产物：`build/application/Release/Program.exe`

> **构建坑（必读）**：
> 1. 改 header（如 `engine_wrapper.h`）后 MSBuild 增量编译**不会**重编依赖它的 .cpp，需 `touch` 该 .cpp 强制重编，否则部署的是旧代码。
> 2. 构建行为异常时优先 `rm -rf build` 重新 configure——**不要复用损坏的旧 CMake 构建目录**。
> 3. 含中文注释的新增源码要存成 **UTF-8 带 BOM**，否则 MSVC 在 GBK 代码页下注释尾字节吞换行（`C4819`/`C2039`）。

也可以在 Visual Studio 中直接打开仓库根目录，使用 CMake 列表（Configure → Build）。

## 5. 构建产物与部署

### 产物位置

| 平台 | 路径 |
|------|------|
| Windows | `build/application/Release/Program.exe` |
| Linux / Android | `build/Program`（历史） |

### 运行位置

实际运行位置为 **`D:/Game/Minecraft/Vector/`** —— 把新的 `Program.exe` 连同 Python 运行时一起复制过去：

```
D:/Game/Minecraft/Vector/
├── Program.exe          ← Py3 版（新）
├── python312.dll        ← Python 3.12 DLL（在 exe 根目录，import-lib 加载）
├── python3.dll, vcruntime140*.dll
├── python312/           ← 27MB 裁剪标准库
│   ├── Lib/             ← 纯标准库（已去 __pycache__/test/tkinter）
│   ├── Lib/site-packages/ ← umsgpack.py、RC4.py、chacha/、raknet/、*.pyi 类型桩
│   └── DLLs/            ← 全部 .pyd 模块
├── source/              ← 框架（init.py 加载插件/处理 RPC 校验；proton.py 解析数据包；redirect.py 遗留）
├── scripts/             ← 插件（每个插件一个目录）
└── Program_py27.exe     ← 旧 Py2 备份
```

> 请勿删改 `source/`，那是运行环境（框架脚本）；插件放 `scripts/`。

### 常用启动参数

```bash
Program.exe --config mc.cfg --logger
Program.exe --start_nethernet --UserID xxx --DisplayName xxx --MD5Token xxx
```

> 完整参数表见仓库 README「命令行参数」一节；插件开发见《插件开发文档》。

### 运行检查

- 日志：`log.txt`（完整）、`dis.log`（断开 / 封禁）
- `PlayStatus value: 3` = **PlayerSpawn（正常进服）**，不是错误；`0` = 登录成功；`1/2/4/5/6` 才是失败
- 反作弊封禁"因违规游戏行为，您的账号被禁止进入游戏" = RPC/MCP 校验链有问题（详见《项目架构与 Py3 迁移》）

## 6. Linux / Android（历史支持）

> ⚠️ 以下内容为 **Python 2.7 时代**的构建方式。Py2→Py3 迁移后，`application/CMakeLists.txt` 通过硬编码的 `PY312_HOME`（Windows 路径）链接 `python312.lib`，非 Windows 构建脚本**尚未同步更新**。如需恢复 Linux / Android 支持，需先：
> 1. 将 `PY312_HOME` 改为可配置（CMake `CACHE` 变量）；
> 2. 移除 `cmake/FindPrebuiltDeps.cmake` 中对 Python 2.7 的处理（或保留 Python 3.12 的构建/查找逻辑）；
> 3. 重新验证 OpenSSL / libdatachannel 等依赖在目标平台的构建。

### Linux x86_64 原生编译（历史命令）

```bash
cmake -B build -DCMAKE_C_COMPILER=clang -DCMAKE_CXX_COMPILER=clang++
cmake --build build -j$(nproc)
```

### Android / Termux 原生编译（历史命令）

```bash
pkg install clang cmake make perl pkg-config
cmake -B build
cmake --build build -j$(nproc)
```

平台检测由 `cmake/Platform.cmake` 自动完成（检测到 Bionic libc 即进入 `PLATFORM_ANDROID` 分支）。也可手动指定 `-DPLATFORM_ANDROID=ON`。

### 交叉编译（Windows → Linux，历史）

```bash
cmake -B build-linux-x64 \
  -DCMAKE_TOOLCHAIN_FILE=cmake/toolchains/linux-clang-x86_64.cmake \
  -DCMAKE_SYSROOT=/path/to/x86_64-linux-gnu-sysroot
cmake --build build-linux-x64
```

> 工具链文件默认 `-target x86_64-linux-gnu`、链接器用 `lld`；`CMAKE_SYSROOT` 需包含目标平台的 GNU 工具链头文件与库。

## 7. 依赖说明

| 库 | 版本 | 构建方式 |
|----|------|----------|
| Python | 3.12.2 | 本机开发安装（`PY312_HOME`）链接 `python312.lib`；运行时部署 exe 旁 `python312/` |
| OpenSSL | 3.5.0 | cmake 配置期自动构建（`cmake/BuildOpenSSL.cmake`），缓存于 `build/_deps/`；Windows 失败时回退到项目自带 `.lib` |
| jsoncpp | 1.9.6 | `add_subdirectory` |
| libdatachannel | 最新 | `add_subdirectory`（含 libjuice、libsrtp、usrsctp） |
| libwebsockets | 4.5 | `add_subdirectory` |
| SLikeNet | 定制（RakNet 魔改） | `add_subdirectory` |
| zlib | 1.3.1 | `add_subdirectory` |

### Python 3.12 运行时部署（排障用）

- **链接**：`${PY312_HOME}/libs/python312.lib`（定义于 `application/CMakeLists.txt`）。
- **部署**：`python312/` 取自本机 Python 3.12.2 的 `Lib/`（裁剪到约 27MB，去掉 `__pycache__`/`test`/`tkinter`）+ `DLLs/`；`umsgpack.py`/`RC4.py`/`chacha/`/`raknet/` 移到 `Lib/site-packages/`；`python312.dll`、`python3.dll`、`vcruntime140*.dll` 放 exe 根目录。
- **旧 Py2 源树**：仓库根目录 `Python-2.7.18/` 与 `Program_py27.exe` 仅作历史参考/备份，构建不再使用。

## 8. 常见问题

### Q: 首次构建很慢？

A: 正常。OpenSSL 需要从源码编译（约 5-10 分钟），产物缓存在 `build/_deps/`，下次构建跳过。Python 3.12 直接链接本机安装，无需从源码构建。

### Q: 链接时报找不到 `python312.lib`？

A: `PY312_HOME` 在 `application/CMakeLists.txt` 里硬编码为 `C:/Users/admin/AppData/Local/Programs/Python/Python312`。确认该路径存在（或改为本机实际安装路径），并勾选安装时的"开发组件"。

### Q: 改完 header 重新构建，但运行还是旧行为？

A: MSBuild 增量编译不重编依赖该 header 的 .cpp。用 `touch <依赖的.cpp>`（如 `CallbackManger.cpp`）强制重编，或直接 `rm -rf build` 全量重建。

### Q: 推送代码到 GitHub 时报 `RPC failed; curl 65 ... Connection was reset`？

A: 仓库历史较大（含 57MB 的 `libcrypto_static.lib`），需要增大 HTTP 缓冲区：

```bash
git config http.postBuffer 524288000
```

### Q: 提示 `libcrypto_static.lib` 超过 50MB 推荐上限？

A: 仅警告，不影响。GitHub 单文件上限 100MB。如需精简仓库，可改用 Git LFS 或重写历史。

### Q: Linux / Android 上 `Python.h` 找不到？

A: Py3 迁移后非 Windows 构建尚未支持（见第 6 节）。历史 Py2 构建时该问题由损坏的 `build/_deps/` 导致，删除后重新 configure 即可。
